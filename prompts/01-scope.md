# 01 — Scope and Define an Oracle

We have a time-limited design/build/demo task. Read the problem statement and relevant repository files and instructions first. **Do not write code yet.**

Return a brief (<= 450 words):
1. Confirmed goal, inputs/outputs, P0 requirements, and assumptions (clearly separated).
2. Up to **three high-impact questions** to ask engineers; omit questions already answered.
3. For each P0 requirement: **observable success criterion + a plausible independent oracle** (supplied expected output, hand-calculated reference, trusted baseline, invariant/property, or live end-to-end result). Clearly mark missing expected answers; do not invent them.
4. A minimal vertical slice and the smallest executable validation check for it.
5. P1/P2 scope, technical/data/permissions constraints, and a fallback if time runs short.
6. Environment readiness: known versus unknown run/test commands and access needed for the agent to observe results.

Avoid premature framework selection, speculative architecture and feature expansion. Stop for human alignment only on consequential ambiguity; otherwise state reversible assumptions and propose the next step.
